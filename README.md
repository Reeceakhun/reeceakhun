## 🔍 How I Work

I debug in public. My commit history isn't a highlight reel — it includes the OIDC subject mismatches, the wrong PAT permission scope, the Git Bash path-mangling that took three tries to spot. I document these in READMEs rather than squashing them away, because the fix is only half the story; the reasoning behind it is what actually transfers to the next problem.

I'd rather understand *why* something broke than just get it passing. When a role assignment turned out broader than it needed to be, or a service account had both a static key and a Workload Identity binding that made the key redundant, I'd rather flag it and explain the tradeoff than leave it unexamined.
